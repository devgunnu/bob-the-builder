# Quality and product workbench

This folder is independent of the implementation owners' files. It prepares evaluation, review, integration, product discovery, and coordination while implementation proceeds.

1. [Evaluation](evaluation.md): a deliberately fictional source and 16 reference cases. Use it for controlled tests, not the real-data demo. Keep the reference cases out of generation prompts.
2. [Review rubric](review-rubric.md): sample selection, decision rules, and a copyable review record.
3. [Acceptance checklist](acceptance.md): local and cloud checks, including failures. Record evidence as work lands.
4. [Behavior brief](behavior-brief.md): a proposed product concept, not an approved contract or an implementation request.
5. [Workstream readiness](workstreams.md): ownership, dependencies, and open verification items. Assigned does not mean active or complete.

Nothing here claims a test has passed. The fixture is useful for controlled evaluation; repeat the exercise on an approved real corpus before drawing conclusions about the demo or product quality.
